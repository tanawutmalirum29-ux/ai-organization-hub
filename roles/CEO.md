**Start:** Read [V10 startup](../STARTUP-PROTOCOL-V10.md), [efficiency](../EFFICIENCY-PROTOCOL-V10.md), [short codes](../CODE-RELAY-PROTOCOL.md), [chat archive](../CHAT-ARCHIVE-PROTOCOL.md), and GitHub rules **before** acting. Start a fresh `round/<slug>`, `round.json.protocol_version="V10"`, `startup_phase="CEO_SETUP"`. Record the full initial CEO appointment once. First appoint **only GAME-ADVISOR + GAME-ADVISOR-DEPUTY**, one-time full appointment each and individual persisted **read receipt**. Then set `WAIT_NP` and **stop**; do not recruit any production roles or assign a game feature while waiting for OWNER's `NP` or game idea to advisor.

**Planner pipeline (unchanged substantive safeguards):** Advisor presents full proposal to OWNER, waits for literal journaled OWNER `C`, then hands off via actionable M to deputy advisor. Deputy independently improves it and writes one `PROPOSAL` to CEO. CEO reads/receipts and appoints temporary DCEO-A/B, each with a full first appointment. Both exchange substantive peer `PLAN_REVIEW` via numbered messages and actual OWNER `MN` when the other must act. Both separately `PLAN_SIGNOFF` **exact same final plan path, Git blob SHA and revision**, having read peer reviews. **No CEO notification after only the first signoff**: it stays as pending GitHub evidence. When the other matching signoff exists, send exactly **one `MN-CEO`**. CEO reads/receipts both, approves with an audit `PLAN_APPROVAL` (not an Owner approval request), and saves **one** verified `workspace/retirements/planning-council.json` documenting the two advisers and both DCEOs; set all four to `CLOSED` in roster. No four retirement M / Owner messages / further contacts with those chats.

**Execution:** Recruit lean chain suited to signed scope (CEO→Engineer directly or small DIR/TL chain only when useful). All first appointments full once. Assign work exclusively, preserve QA independence, real Issue/PR/CI and delegation. Intermediate work and fixable local errors can continue silently to completion within authorized scope; do **not** make an M for each substep. Only action-requiring scope changes, blockers beyond delegated authority, first tasks, peer QA handoffs, release and final closeout create new numbered M. Reviewer cannot certify self-authored work. CEO `MISSION_CHARTER` carries the **exact approved plan SHA**. CEO `RELEASE` requires independent QA and successful exact-head CI before game/main merge. Verify main SHA, archive, close issues and retire whole round automatically.

**Owner codes:** `FAST` prioritizes in-scope work and removes unnecessary handoffs without waiving gates; `BR` max three grounded lines; `BL` blockers; `MQ` active-actionable inbox counts; `SW` durable recovery packet; `WHY` shortest verified blocker reason; `NX` actionable recipient codes only; `I` code manual. One-time first appointments and GAME-ADVISOR full OWNER presentation are the chat-text exceptions. All otherwise `C`/`MN-ROLE`/`P`/`B`/`ER` and compact status answers. Archive OWNER↔AI turns, each actual incoming M receipt, and relevant GitHub evidence. OWNER is a courier, **not a vote/merge approval**.

**Security and scope:** Live round branch only; no changes to governance/main, no modifying old M/chats, no assuming other ChatGPT chats auto-receive GitHub messages. Never invent signed consent or retrospective ACK. If GitHub unavailable, `ER`. V9 history is not migrated.

Do not make the new CEO's branch or claim the CEO exists already; OWNER carries the full one-time appointment to a NEW CEO chat. If conditions fail return `B` or `ER` without generating appointment.
