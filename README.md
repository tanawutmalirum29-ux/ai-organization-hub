# Ant Kingdom — ระบบบริหาร AI แบบง่าย

ใช้คลังนี้เป็น **กฎและคู่มือคำสั่งย่อ** สำหรับการทำเกม [Ant Kingdom](https://github.com/tanawutmalirum29-ux/ant-project) ไม่มีขั้นตอนบริหารหลายชั้นที่บังคับทุกงาน

## เริ่มตรงไหน

- [RULES.md](RULES.md) — **กฎกลางฉบับเดียว** (รับงาน → ทำ → ทดสอบ → ส่งมอบ)
- [COMMANDS.md](COMMANDS.md) — เก็บคำสั่งย่อเดิม `MN`, `TR`, `ST`, `NX`, `CI`, `SYNC`, `C`, `ER` และคำสั่งอื่น
- [OWNER-TO-CEO.md](appointments/OWNER-TO-CEO.md) — ใบแต่งตั้ง CEO ฉบับสั้น

## วิธีทำงาน

1. OWNER ส่งโจทย์ให้ CEO หรือผู้พัฒนาที่ได้รับมอบหมายอยู่แล้ว
2. งานเล็ก CEO ทำเอง; งานใหญ่แบ่งให้ Engineer 1–3 คน โดยแยกขอบเขตไฟล์และ Branch
3. Engineer เขียนโค้ด ทดสอบ และเปิด PR; OWNER ส่งผลระหว่างแชทเมื่อจำเป็น
4. CEO ตรวจ CI/QA รวมระบบ แล้ว Merge เข้าเกม `main` เมื่อผ่านจริง
5. สรุปผลสั้น ๆ พร้อม Commit SHA, PR และรายการที่ยังค้าง

**ไม่ต้องสร้าง** Round Ledger, `M00000`, Read Receipt, Chat Event, Roster, สภาที่ปรึกษา, PLAN_SIGNOFF หรือองค์กรเต็มรูปแบบเพื่อเริ่มงานปกติ

## การใช้คำสั่งย่อ

ส่ง `MN` ในแชทที่ทำงานอยู่ = ตรวจงานและลงมือทำต่อ  
ส่ง `TR` = ตรวจสาเหตุแล้ว Retry เฉพาะส่วนที่ยังไม่สำเร็จอย่างปลอดภัยหนึ่งครั้ง  
ส่ง `ST` = ขอรายงานสถานะจริง  
ส่ง `NX` = ขอข้อความส่งต่อที่ OWNER ต้องคัดลอกไปอีกแชท

**AI ในคนละแชทไม่ได้รับข้อความ GitHub หรือข้อความจากแชทอื่นโดยอัตโนมัติ** OWNER ต้องส่งต่อด้วยตนเองเมื่อจำเป็น

## โค้ดเดิม / เครื่องมือเดิม

`scripts/` และ `tests/` ที่รองรับองค์กรแบบหลายชั้นยังอยู่เพื่อความเข้ากันได้กับงานเก่า แต่ **ไม่ใช่ขั้นตอนบังคับในกฎใหม่**; ระบบ CI ของ Governance ตรวจเฉพาะโครงสร้างกฎและคำสั่งปัจจุบัน ส่วนเกมยังต้องใช้ Native Tests/Build/Browser QA จริงที่คลังเกม

งานค้างก่อนการเปลี่ยนแปลงนี้ยังคงอยู่ตามสถานะ GitHub จริง ไม่ถือว่ายกเลิกหรือผ่านการตรวจโดยอัตโนมัติ

## ความปลอดภัยและการปิดงาน

ห้าม Commit ความลับลง Public Repo ห้ามอ้างผลทดสอบหรือ Commit ที่ยังไม่ยืนยัน การปิด Issue/ลบ Branch ไม่ใช่การลบ GitHub History; `PF` เป็นการตรวจปิดงาน ไม่ใช่การลบข้อมูลโดยอัตโนมัติ
