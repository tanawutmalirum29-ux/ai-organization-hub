# Ant Kingdom — AI Organization Governance

เอกสารกลางสำหรับการจัดตั้งและบริหารทีม AI ที่ร่วมพัฒนา [Ant Kingdom](https://github.com/tanawutmalirum29-ux/ant-project)

## เอกสารทางการ

| เอกสาร | วัตถุประสงค์ |
|---|---|
| [RULES.md](RULES.md) | ข้อบังคับองค์กร บทบาท ขั้นตอนการทำงาน การตรวจรับ และการปิดภารกิจ |
| [COMMANDS.md](COMMANDS.md) | คำสั่งสั้นสำหรับ OWNER และการส่งงานระหว่างแชท |
| [OWNER-TO-CEO.md](appointments/OWNER-TO-CEO.md) | แบบแต่งตั้ง CEO สำหรับภารกิจใหม่ |

**แหล่งอ้างอิงข้อบังคับ:** `RULES.md` ใน `main` เป็นเอกสารกฎองค์กรที่ใช้ในการดำเนินงาน ส่วนเอกสารอื่นมีหน้าที่อธิบายและช่วยปฏิบัติตามกฎนี้

## โครงสร้างการดำเนินงาน

- `main`: ข้อบังคับ แบบแต่งตั้ง เครื่องมือตรวจสอบ และเทมเพลตทั่วไปเท่านั้น (ห้ามเก็บประวัติโครงการเก่า)
- `round/<round-id>`: ข้อมูลภารกิจ สมาชิก ข้อความ แผน และผลการทำงานชั่วคราว ต้องล้างเมื่อจบรอบ
- [Game repository](https://github.com/tanawutmalirum29-ux/ant-project): โค้ดเกมปัจจุบัน; Issues, PRs และผล QA ใช้ชั่วคราวระหว่างภารกิจ

แต่ละภารกิจเริ่มต้นด้วย CEO ที่ได้รับแต่งตั้งใหม่ จากนั้นแต่งตั้งผู้ร่วมงานตามขั้นตอนใน [RULES.md](RULES.md) โดย OWNER ทำหน้าที่ส่งข้อความข้ามแชทเท่านั้น การดำเนินงานด้านเทคนิคและการตัดสินใจภายใต้ภารกิจเป็นหน้าที่ของ AI ตามสายงาน

## การสื่อสารและการติดตามงาน

ข้อความที่ต้องส่งให้ AI อีกแชทหนึ่งบันทึกเป็น `M` ใน GitHub จากนั้น OWNER ส่ง `MN` ไปยังแชทผู้รับ ผู้รับตรวจข้อความ ประวัติแชท และหลักฐานผลงานจริงก่อนทำงานค้างต่อ ไม่ต้องเขียน Receipt หรือบันทึกการอ่านทุกครั้ง ระบบติดตามคำตอบที่มี `in_reply_to` และตรวจการอนุมัติจากหลักฐานแผนและ QA ที่เกี่ยวข้องจริง

## เครื่องมือปฏิบัติงาน

| คำสั่ง | การใช้งาน |
|---|---|
| `node scripts/inbox.mjs workspace <ROLE_ID> <APPOINTMENT_ID>` | ตรวจข้อความที่ยังไม่มีผลตอบกลับโดยตรงของผู้รับ |
| `node scripts/courier.mjs workspace` | ตรวจรหัสส่งต่อที่ OWNER ต้องนำไปส่ง |
| `node scripts/message-queue.mjs workspace` | สรุปข้อความที่ยังไม่มีผลตอบกลับตามผู้รับ |
| `node scripts/org-dashboard.mjs workspace` | สร้างภาพรวมสถานะภารกิจจาก GitHub |
| `node scripts/validate-governance.mjs` | ตรวจข้อมูลและหลักฐานตามข้อบังคับ |
| `node scripts/org-sim.mjs` | ทดสอบกระบวนการขององค์กรแบบจำลอง |
| `node --test tests/*.test.mjs` | ทดสอบกฎและเครื่องมือด้วยกรณีทดสอบอัตโนมัติ |

การใช้สคริปต์ในเครื่องไม่ได้ส่งข้อความเข้า ChatGPT แชทอื่นเอง และผลทดสอบแบบจำลองไม่สามารถแทนการตรวจสอบการทำงานจริงบนเกมได้

## การดูแลข้อมูล

Repository นี้เป็นสาธารณะ ตรวจทานก่อนบันทึกข้อความและหลักฐาน ห้ามเผยแพร่รหัสผ่าน Token ข้อมูลส่วนบุคคลที่ละเอียดอ่อน หรือบทสนทนาส่วนตัวโดยไม่มีเหตุจำเป็นและสิทธิ์ที่เหมาะสม

## การปิดงานแบบไม่เก็บข้อมูลโครงการเก่า

ตาม [RULES.md](RULES.md) หมวด 8: เมื่อภารกิจสำเร็จหรือยกเลิก ต้องเหลือเพียง `main` ใน **ทั้งสอง Repository** และล้าง Issues/PRs/Tags/Releases/Artifacts/Workspace/Archives/บันทึกโครงการเก่าออกจริง ห้ามคัดลอกหรือเก็บประวัติโครงการบน governance `main`. โค้ดเกมและสินทรัพย์ที่รับรองแล้วบน game `main` ต้องคงไว้เพื่อพัฒนาต่อ. การ Reset Branch หรือ Close Issue ไม่ใช่การลบประวัติ; ถ้าต้องไม่เหลือ Git/PR History จริงต้องให้ OWNER สร้าง Repository ใหม่จาก Snapshot ของไฟล์ `main` ปัจจุบัน และตรวจสิทธิ์/Actions/Deploy ใหม่ทั้งหมด. `PF` และ `Completed` ต้องอิงหลักฐาน GitHub จริงเท่านั้น
