# AI Project Governance

ระบบกลางสำหรับ **แต่งตั้ง AI และบริหารงานทุกประเภทโปรเจกต์** โดยใช้ GitHub เป็นพื้นที่ทำงานร่วมกันและส่งมอบผลลัพธ์จริง

## เริ่มงาน

1. OWNER ระบุเป้าหมายและลิงก์ `PROJECT_REPO` ของโปรเจกต์ที่จะทำ
2. แต่งตั้ง CEO ตาม [แบบแต่งตั้ง](appointments/OWNER-TO-CEO.md) หรือมอบหมายต่อผ่าน Issue ของโปรเจกต์
3. CEO วางแผน แบ่งงาน ลงมือทำ ตรวจคุณภาพ และส่งมอบลง `PROJECT_REPO/main`
4. เมื่อเสร็จงาน ให้ดำเนินการ **PF (Post-mission cleanup)** ตามกฎทันที เพื่อให้เหลือเฉพาะผลลัพธ์ที่ใช้งานจริงบน `main`

## เอกสารใช้งาน

- [RULES.md](RULES.md) — กฎกลางฉบับเดียว รวมบทบาท การแต่งตั้ง คุณภาพ และขั้นตอนคืนสภาพหลังจบงาน
- [COMMANDS.md](COMMANDS.md) — คำสั่งย่อ `I`, `C`, `MN`, `TR`, `ST`, `NX`, `PF` และอื่น ๆ
- [appointments/OWNER-TO-CEO.md](appointments/OWNER-TO-CEO.md) — เทมเพลตแต่งตั้งที่กำหนดโปรเจกต์ได้ทุกครั้ง

**ข้อความถึง OWNER:** ค่าเริ่มต้นตอบ `C` เมื่อไม่มีงานส่งต่อ หรือหนึ่งบรรทัด `ROLE: MN #<issue> <url>` / `ROLE: AP-ROLE #<issue> <url>` เมื่อมีงานส่งต่อ รายละเอียดเก็บใน Issue/PR; หากขอสถานะหรือคำอธิบายให้ตอบตามนั้น

**ขอบเขต:** ชื่อโปรเจกต์ ลิงก์รีโปและเกณฑ์ทดสอบต้องอ่านจากคำสั่งงานปัจจุบัน ไม่กำหนดตายตัวในคู่มือนี้

**ข้อจำกัดของการคืนสภาพ:** ลบ Branch และไฟล์ที่ไม่ใช้ได้ แต่การเริ่มเลข Issue และประวัติ Commit ใหม่อย่างแท้จริงต้องสร้าง Repository ใหม่และตรวจการย้ายระบบ. ห้ามอ้างว่ารีเซ็ตเสร็จจนกว่าจะตรวจสอบได้จริง
